# M8.1: Real data (live keys and a real hack)

## In one sentence
M8.1 runs Unmask against **real services and real hacks**: every API key was tested live, four real exploits (Euler, KyberSwap, Harmony, Beanstalk) can be loaded from the website, and every place where real data broke an assumption the simulator had hidden was fixed.

## 1. Every service, tested live
A throwaway script called each service with the keys in `backend/.env`, printing only "works" or "fails" and never a key.

| Service | Result |
|---|---|
| MongoDB Atlas | ✅ ping, write and delete |
| Etherscan V2 | ✅ Ethereum and Arbitrum on the free tier |
| Alchemy | ✅ live block number; mempool check |
| GitHub | ✅ 5,000 requests an hour, code search |
| Groq / Gemini | ✅ after fixing the retired models (below) |
| Discord webhook / Telegram bot | ✅ test alert delivered |

The full pipeline then ran on Atlas: simulated attack, real OSINT collection (77 RSS + 79 GitHub posts), AI-worded explanations, and one approved alert sent to Discord and recorded in the audit chain.

## 2. Loading a real hack from the website
The case file now has a **Real hack** picker next to the simulated one.

1. Pick a case, for example **Euler Finance exploit (13 March 2023, ~$197M)**.
2. Click **Load real hack**. The first load fetches the transactions from Etherscan (about 1–2 minutes). After that they're cached and it takes seconds.
3. The analysis runs automatically. You get the 3D money graph, where the money is now, exits, freeze letters, the timeline and the matrix, all from real chain data.

How a case is defined, and the rules for adding one: [data/replays/README.md](../../data/replays/README.md).

**The Euler case:**
- **Seeds:** the attacker's address (`0xb66c…95db`, "where funds remain") and the pass-through to Tornado Cash (`0xc66d…3c9a`), both copied from the rekt.news post-mortem.
- **Victim:** Euler's recovery Safe (`0xcad0…1dce`, tagged "Euler: Multisig 2" on Etherscan), where the hacker sent the money back.
- **Window:** 12 March – 10 April 2023.

| What Unmask finds | Value |
|---|---|
| Transfers loaded | 1,334 (real) |
| Attacker-cluster wallets | 19 |
| Traced through the attacker's wallets | $191.6M (the reported loss is ~$197M) |
| Given back to the victim | $189.4M to Euler's multisig |
| Into Tornado Cash | $1.8M |
| Reached an exchange | $0.16M at Binance, with a freeze letter in the dossier |
| Suspects | none, because there are no 2023 posts in the case; correctly, no one is named |

## 3. What real data broke, and the fixes

| Problem found on real data | Cause | Fix |
|---|---|---|
| The AI summary toggle silently showed plain text | Both default models had been retired | Defaults are now `openai/gpt-oss-120b` (Groq) and `gemini-flash-latest` (Gemini) |
| AI answers came back empty or cut mid-sentence | The new models "think" first, and that used 78 of 80 tokens (Groq) and 384 of 400 (Gemini) | Groq: low reasoning effort. Gemini: thinking off. |
| An empty Groq answer never tried Gemini | An empty string counted as success | Empty = miss, so it falls through to the backup (tested) |
| The AI wrote "his posts" about an unknown person | It added a fact the evidence didn't support | The prompt says to refer to people as "they" |
| The Euler load ran for many minutes | It kept downloading after the 3,000-transfer cap and discarded the results | It stops at the cap (tested) |
| The data spanned 2021–2026 | No time limit on the trace | A `window` in the replay file, fetched by block range on Etherscan's side (tested) |
| Spam tokens filled the case | Airdrops scammers send to famous hacker wallets | Unpriced tokens are dropped from replays (tested) |
| The Tornado Cash Router was followed like a normal wallet | It was missing from the labels | Added after confirming via Etherscan's verified source (`TornadoRouter`) |
| **The victim's recovery Safe was flagged as the attacker's** ($505M "held") | The simulator never has third-party contracts, so every unlabeled address the money touches joined the cluster | Contracts in the cluster that the attacker didn't deploy become "Someone else's contract" hubs, then it re-clusters (tested) |
| "~100% of the stolen funds will reach Binance in ~0h" | One $60K deposit (0.04%) was extrapolated to $170M | A cash-out pattern needs ≥5% of the money behind it before the rest is predicted (tested). "0h" now reads "~17 min". |
| "Posts like UTC+9" on a case with no posts | The clock kept the previous case's suspect | It's cleared when the new case has no suspect |
| The legend listed "Decoy (planted)" on a real case | Fixed list | It lists only the kinds actually in the graph |
| "$169.7M stolen" with no victim known | The label assumed a measured theft | Reads "traced through the attacker's wallets" when no theft was observed |

Tests: 175 passing (6 new checks).

## 4. "Show me on other data": three answers for judges

| Ask | What to do | What it proves |
|---|---|---|
| "Try another attack" | Type any number in **Attack** and click **Load simulated attack** | Every number except 7 (the story's) is a **different attacker**: name, amount ($8M–$150M), time zone and wallet count all change. On 20 random numbers the engine named the right attacker every time (100% precision, ≥99.7% recall). The time zone was exact in 17 of 20 and 3–4 h off in 3. |
| "Show another real hack" | Pick **KyberSwap**, **Harmony** or **Beanstalk** under **Real hack** | Each is checked against the public record (table in section 5). |
| "Use an address I choose" | Open **Trace any address**, paste the address from any post-mortem, pick the dates and chain, click **Trace** | The judge picks the data. It's traced live from the blockchain (a few minutes the first time, then cached). |

The simulator change lives in `simulator.variant(seed)`. The website uses it, while the tests keep the fixed attack-7 story, and a new test runs the whole engine on four different attackers.

Also fixed: Etherscan error answers ("chain not on the free plan", "invalid key") were being cached as "no transactions", so one bad moment was remembered forever. Errors are no longer cached (tested).

## 5. "Held" balances made right (Harmony and Beanstalk added)

Harmony and Beanstalk were left out because their numbers were wrong. Finding why fixed Euler and KyberSwap too.

| Problem found on real data | Cause | Fix |
|---|---|---|
| Harmony: $57M stolen, but hundreds of millions "held" | Only the first 1,000 rows of a wallet were read, and the 3,000-transfer cap cut wallets halfway | Every page is read. A wallet is loaded whole or not at all, and only whole wallets count as "held" (tested) |
| A swap's USDC-out merged with its WETH-in | Etherscan V2 has no `logIndex`, so every token row in a transaction got the same id | The id includes the token, sender, receiver and amount (tested) |
| Harmony's 85,700 ETH Tornado deposits came from ETH the hacker "never had" | Contract-paid ETH (swap payouts, WETH unwraps) is an internal transfer, which wasn't read | Internal transfers are loaded, and WETH wraps/unwraps get their WETH side added (tested) |
| Tornado deposits showed $0 "in mixers" on every real case | Only the simulator tagged moves as mixer/bridge/DEX; real traces stayed "transfer" | Each move's role is stored when a case loads (tested) |
| Euler: $272M "held" in look-alike addresses | Address-poisoning scams emitted fake "DAI" transfers, and tokens were priced by name | Priced only by their real contract address. Look-alikes become `fake:DAI`, never counted (tested) |
| Beanstalk: "$0.1M traced" once its profit was in Tornado | With no theft seen, the total counted only money still held | Total = held + sent to mixers and bridges + given back to the victim (tested) |
| KyberSwap graph failed to load | 12 moves in the same second gave the bot test a zero time scale, NaN, and broken JSON | Same-second bursts score as fully machine-like (tested) |

| Case | What Unmask finds | Public record |
|---|---|---|
| Euler (Mar 2023) | $191.6M traced, $189.4M given back to Euler | ~$197M, nearly all returned |
| KyberSwap (Nov 2023) | $33.5M traced on 3 chains, $10.3M into Tornado | ~$48M |
| Harmony (Jun 2022) | $72.3M stolen, $98.1M into Tornado in 857 deposits of 100 ETH | 85,700 ETH (~$98M) into Tornado by 2 July (Elliptic) |
| Beanstalk (Apr 2022) | $74.4M traced, $74.3M into Tornado | ~$76M profit |

The money panel has a new row, **Given back to the victim**, and the route chart a matching box.

Tests: 192 passing.

## Limits that remain
- Tokens without a known price (WBTC, AAVE, LP tokens…) aren't counted, so Harmony's stolen total ($72M) is below the reported ~$100M.
- Wallets past the last hop, or too busy to load whole, aren't counted as held: money that reached them was only "last seen" there. KyberSwap's busy DEX pools are why it's $33.5M against ~$48M.
- `data/cache/` is gitignored, so a fresh server (Render) fetches each case again on its first load (1–5 minutes).
