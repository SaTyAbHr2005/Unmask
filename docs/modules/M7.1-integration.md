# M7.1: Integration pass (connecting the features that were built but unused)

## In one sentence
A feature audit after M7 found **7 features that were built and tested but never called by the running app**, plus two pitched ideas (time-to-freeze, optional AI wording) that weren't wired. This pass connects all of them to the pipeline and the API, so the dashboard (M8) can show them.

## What the audit found, and what changed

| # | Feature | Before | Now |
|---|---|---|---|
| 1 | Threat-feed scrapers (RSS, Telegram) | Worked, but no endpoint used them, so real cases had no OSINT | `POST /api/osint/collect` |
| 2 | GitHub monitoring | Same | Same endpoint; also **searches GitHub for the case's attacker wallet address** |
| 8 | Mempool watch | Function existed, no endpoint | `GET /api/mempool` |
| 14 | Wallet × time matrix | Used nowhere | `GET /api/matrix` |
| 15 | Wallet behaviour vectors | Used nowhere | Computed for every attacker wallet in `run()`; shown by `GET /api/wallet/{addr}` |
| 20 | Amount conservation (subset-sum) | Used nowhere | **Deposit composition**: which laundered pieces make up each exchange deposit |
| 21 | Bot detection | Computed, but invisible | `bot_score` on every graph node and on the wallet page |
| (idea) | Time-to-freeze | Pitched, never computed | `timing` in `/api/money-now` and `/api/report` |
| (idea) | AI-worded explanations | Existed, but always off | `?polish=true` on `/api/links` and `/api/report` (top 3 only) |

Feature tally after this pass: **35 of 44 fully wired**, 8 waiting only for their screen in M8 (#33–38, #40, #42), and 1 to build in M8 (#44 privacy masking).

## New pipeline outputs (`pipeline.py`, `amounts.py`)

### Deposit composition: "this deposit is made of these 34 pieces"
`deposit_composition(transfers, wallets, labels)` in [amounts.py](../../backend/gt/analytics/amounts.py), for every deposit from an attacker wallet into an exchange:
1. **Full sweep:** do *all* the pieces this wallet received before the deposit add up to the deposit (±0.5%)? That's the usual consolidation move.
2. Otherwise **subset-sum:** find the specific combination of incoming pieces that adds up (M4's `match_split`).
3. Otherwise **unmatched**.

Each result lists the deposit transaction, wallet, exchange, asset, amount, USD, the **transaction hashes of the pieces**, how many, and which method matched. That's hard evidence for an exchange: *"this 1,737 ETH deposit is exactly the sum of these 34 transfers, each traced back to the theft."*

**Simulator:** Exch-A 1,737 ETH = 34 pieces; Exch-A 1,349 ETH = 34 pieces; Exch-B 1,769 ETH = 33 pieces. All are full sweeps of laundered mixer outputs. (Bridge withdrawals deposited straight to an exchange are single pieces; the report shows only real reconstructions with 2 or more.)

### Time-to-freeze: the window to act
`Results.timing`:

| Field | Meaning | Simulator |
|---|---|---|
| `theft_ts` | First transfer out of the victim into the cluster | t0 |
| `first_cashout_ts` / `time_to_first_cashout_s` | First deposit at an exchange, and how long after the theft | **20.1 h** |
| `prewarn_ts` / `prewarn_lead_s` | When the pre-attack warning fired, and how long **before** the theft | **5.5 h before** |
| `next_predicted_exit_s` | Soonest predicted arrival of the money still held | **~10.8 h** |
| `case_now_ts` | The case's "now" (latest blockchain transfer) | — |

This is the pitch in numbers: *"we warned 5.5 hours before the theft; the team had 20 hours before the first cash-out; the next wave is expected in about 11 hours."*

### Wallet behaviour vectors
`Results.features` holds, for every attacker wallet, the M4 vector: transaction count, gas mean and spread, round-amount share, gap mean and variation, active hours. Example, the hacker's main wallet: 327 transactions, **gas always exactly 25 gwei (spread 0)**, 3% round amounts, bot score **0.88**.

### A bug found while wiring (fixed)
Collecting **real** OSINT (2026 posts) into a **simulated 2025** case made every link look a year old, and decay pushed the hacker from 86% to almost 0%; a news feed ended up "top". The same would happen on a replay of any older real hack. **Fix:** the case's "now" is the time of the latest **blockchain** transfer; newer posts no longer age the case. A regression test covers it. After the fix, with 136 real posts mixed in, the hacker stays on top at **86% (high)**.

## New and changed API endpoints (`api.py`)

| Endpoint | Returns |
|---|---|
| `POST /api/osint/collect` | Body (all optional): `{"rss": true, "github_queries": [...], "telegram_channels": [...], "search_case_addresses": true}`. Collects RSS + GitHub (+ Telegram if set up), adds posts and the clues found in them to the case, and reports counts per source. Then call `POST /api/run` to rescore. A dead source never fails the call. **Live test:** 77 RSS + 59 GitHub posts, 36 clues, 11.6 s. |
| `GET /api/mempool` | `{"available", "pending", "watching"}`: unconfirmed transactions touching the attacker cluster right now. `available: false` without `ALCHEMY_API_KEY`. |
| `GET /api/wallet/{addr}` | One wallet: label, cluster, kind, behaviour vector, bot score, time zone, holdings, deposit compositions, last 25 transfers. **400** for a malformed address, **404** if unseen. |
| `GET /api/matrix?cluster=0&bucket=3600&top=40` | The ledger as a matrix: the cluster's busiest wallets × time buckets → transaction counts (for a heatmap grid) |
| `GET /api/graph` | Nodes now include `bot_score` |
| `GET /api/money-now` | Now includes `timing` |
| `GET /api/report` | Now includes `timing` and `deposits` (reconstructions with ≥ 2 pieces) |
| `GET /api/links?polish=true`, `GET /api/report?polish=true` | AI-worded one-line summary in front of the top 3 explanations (Groq/Gemini). Off by default; template text if no key. |

## How to test
From `HackForge`:

```bash
py -3.11 -m pytest backend/tests/test_amounts.py backend/tests/test_pipeline.py backend/tests/test_api.py -q
```

New tests: deposit composition (full sweep, subset-sum, unmatched, ignores later inflows), deposits in results, time-to-freeze fields, wallet features saved, **newer OSINT doesn't age the case**, OSINT collect (including the case-address search and the Telegram pass-through), mempool with and without key, wallet detail (+400/404), matrix, bot scores on graph nodes, timing and deposits exposed, AI polish only when asked and only for the top 3.

Full suite: **170 tests**.

Try it live (server running on port 8000):

```bash
curl -X POST http://localhost:8000/api/osint/collect -H "Content-Type: application/json" -d "{}"
```
```bash
curl -X POST http://localhost:8000/api/run
```

## Limitations
- OSINT collection runs on demand (one call), not on a schedule.
- GitHub code search needs `GITHUB_TOKEN`; without it only commit messages are searched.
- A wallet's own time zone (wallet page) is less reliable than the cluster's: one wallet's activity can be bunched into a few hours. The cluster-level estimate (UTC+9) is the one used as evidence.
- Deposit composition ignores earlier deposits from the same wallet (it assumes one sweep per wallet).
